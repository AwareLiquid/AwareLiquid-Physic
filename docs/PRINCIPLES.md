> 制度形式移植自 M1 仓库 `docs/guides/ITERATION_PRINCIPLES.md`（PIEVO 方法论：原则可进化的科学发现）。
> 本文件是**事实来源为 `docs/PRD.md`（7 波 A100 训练）与 `docs/architecture.md`（ADR）**的提炼层：每条原则 = 陈述 + 状态 + 证据链 + 待消不确定性。

## 1. 原则台账

### P1 — 守恒进架构（硬约束）优于进损失（软约束）· **状态：SUPPORTED（最强）**

- 证据：v0.1 轨道 100 步能量漂移 6.2 vs 无结构基线 37.8（3-6×，`benchmarks/physics_rollout_eval.py`）；**第八波 P0-3 收口（`energy_drift_eval.py`）：新 context + 半群配方下 orbit 100 步漂移 1.75±0.51 ≤ 记录基线 6.2，且优于 v0.1 架构同协议重测锚点 3.33（记录基线复现核查 5.55）**；v0.2 扩展到六类物理系统全部成立——非可分（隐式中点，ADR-8）rollout_mse **1.66e-5**（50000 步，持续收敛）、时间条件化 **2.57e-6**（10000 步最佳）、2D 谱算子守恒测试 2.9e-7、随机权重（未训练）漂移 1.6e-6 有界（守恒是架构性质，不需训练）。
- 出处：PRD §1、§6、§10–§17；ADR-1、ADR-8、ADR-9。
- 边界（诚实）：时间条件化系统 H(q,p,t) 能量**不守恒是物理正确**（受迫系统外力做功，ADR-9）——守恒保证只在时间无关极限恢复。真-ω 能量诊断把隐藏参数辨识误差计入漂移：spring 族上 liquid final 漂移（0.205）高于 static（0.081）但呈有界振荡（drift_max 0.245 反低于 static 的 0.371），是 ω̂≠ω 的诊断口径效应而非守恒退化（PRD §17）。
- 待消不确定性：无核心争议；守恒指标自动化回归已落地（结果 JSON `meta` 溯源块 + `benchmarks/audit_results.py --check` + `energy_drift_p03.json` 逐 seed 漂移曲线 JSONL）。

### P2 — 半群训练（轨迹内任意时间对）应是所有任务的默认训练方式 · **状态：SUPPORTED**

- 证据：第五波（PRD §13）——M1 的 liquid 优势从 21%（固定窗口）跃升到 **61.5%（CPU）/ 81.1%（GPU）**；第六波 7 配置稳健性：**32.6%~85.6%，均值 ~66%**，全部超过 P0-1 的 30% 目标；第七波 10000 步达 **90.4%**，优势随步数单调增长。"GPU 数据退化"不是数据问题，而是固定窗口训练过拟合（train_loss 1.2e-2 但 rollout 发散）。**第九波样本效率双曲线（PRD §18，`sample_efficiency_eval.py`）再确认**：同等预算 @512 all2all 1.04 vs prefix 2.77（深 2.7×），seed 0 与第五波记录逐位一致；all2all@128 优于 prefix 全阶梯最佳（prefix 饱和 ~2.5）。
- 出处：PRD §13、§14、§16、§18；ADR-5。
- **台账价值的活例子**：第 9 节曾写下"平台期结论——M1 21% 到顶"，一个波次后被半群训练推翻。"平台期"可能是**训练方式**的瓶颈而非架构瓶颈。
- 边界（诚实）：「同等 MSE 所需样本 ≤ 1/5」（P1-1 字面口径）**不可闭合**（第九波）——prefix 在 n≈128 饱和后，可达水平上两循环样本数相同（plateau 简并），更深水平 prefix 不可达（下界 4×，上界无界）。半群效率的真实形式：**同等数据打开 prefix 不可达的精度区间**。
- 待消不确定性：半群训练对 M2（场任务）增益幅度未单独量化（M2/M3 的经验只间接支持）；半群小样本端（n<128）反而劣于 prefix 的现象（本轮 32/64 档）未归因。

### P3 — liquid 系统辨识的增益集中在"有隐藏参数族"的任务；齐次任务 static 已足够 · **状态：SUPPORTED**

- 支持：M1 弹簧族（隐藏刚度 ω）66–90%；M3 few-shot **3.24x**（单 seed 最佳）/ ~2.9x（3 seeds 均值 2.67/2.67/3.24）。
- 反面（同样重要）：2D 周期膜 static 1.78e-3 **优于** liquid 1.09e-2（齐次系统无需辨识）；M2 非均匀 1D 5 seeds 接近打平（1.93e-2±4.3e-4 vs 1.75e-2，不稳健）；N-body 混沌系统 liquid 仅 1.7%（14.62 vs 14.87，第一波；更大模型 15.41±1.08 无益，第三波）。
- 出处：PRD §9、§10（核心结论段）、§11、§12。
- 待消不确定性：隐藏参数"可辨识度"（观测窗口内信息量）与 liquid 增益的定量关系未建模——选任务时目前靠直觉。

### P4 — FiLM 条件化必须配长窗口/半群训练；短窗口下 concat 更稳 · **状态：SUPPORTED（负结果教训）**

- 证据：M1-FiLM 消融：短窗口（k_train=8）+ 小系统下 FiLM 的 train_loss 更低（1.7e-2）但 100 步 rollout 发散 9-18×——每层调制使势能对 context 过度敏感；post-activation FiLM 无界 → 力场爆炸（mse 51.7），pre-activation（Tanh 前）修复（ADR-7）。
- 出处：ADR-4（实测修订）、ADR-7；PRD §9 M1 行。
- 推论：条件化机制的表达力排名（concat < FiLM < hypernetwork）不等于好用排名——**正则压力（训练方式）先于机制选择**。半群训练下 FiLM 在 M2 稳定，佐证此序。

### P5 — GPU/CPU 生成数据分布不可比 · **状态：KNOWN-ISSUE**

- 证据：第一波 M1 GPU 数据 7.57 vs 3.21（liquid 无优势）再现于第三波 3000 步；同期 CPU 数据记录 21%。CUDA generator 与 CPU generator 采样分布不同，跨 device 的结果**不可比**，device 内可复现。
- 出处：PRD §10（⚠️ 行）、§11（待诊断行）、§13（半群解释部分消解了"退化"但分布差异本身未诊断）。
- 待消不确定性：差异的确切来源（采样路径 vs 数值精度）未定位；缓解现状是"对比实验只在同 device 内做"，已写入结果 JSON 的 `meta.device` 字段使 device 可审计。

### P6 — 单 seed 结论不可信，多 seed 协议是必须 · **状态：SUPPORTED**

- 证据：M2 非均匀介质增益 seed 依赖（漂移优 40% 或 MSE -16.5%，不稳健）；概率化 seed 0 = 0.98 vs seed 1 = 2.28；N-body seed 1 = 9.90。第四波统计验证后 M3 的 3.24x 修正为均值 ~2.9x。
- 出处：PRD §9（P2 进展·多 seed 协议）、§11、§12。
- 制度化：`field_eval` / `nbody_eval` 已有 `--n_seeds`（均值±std）；其余 benchmark 报单 seed 值时，结论措辞必须带 seed 号。

### P7 — 在固定架构+任务+训练方式下，继续加大预算不再增益；突破来自训练方式/架构/任务层的变化 · **状态：UNCERTAIN（一半已被 P2 修订过一次）**

- 证据（支持）：第 9 节平台期——M1 21%、M2 不稳健、M3 ~2.4x 时加大预算无益；第七波概率化 5000 步 1.18（3000 步 0.98 更优，长训练无益）；2D 8.4M 参数高分辨率成本高。
- 反证（警惕过度引用）：M1 的"平台期"被**训练方式**变化（半群）打破并超额 2.2 倍——所以"平台期"的正确响应顺序是：先换训练方式（最便宜），再换任务，最后才换架构。
- 出处：PRD §9（平台期结论）、§13、§16。
- 待消不确定性：当前新平台期（第七波后）在哪一层——候选见 §2 实验队列。

## 3. 制度（防止回退到"叙事驱动"模式）

1. **本文件是活台账**：每波 benchmark 结束，先更新原则状态，再决定下一个实验。原则状态变化 = commit message 的一等公民（如 `docs: P2 从 UNCERTAIN 升为 SUPPORTED（第六波 7 配置）`）。
2. **异常晋升规则**：同一异常出现 ≥2 次 → 强制原则修订评审，禁止用"再加一个模块"响应异常（先例：GPU 退化再现两次 → 半群假说取代"数据问题"假说）。
3. **新机制准入 = 预注册 kill criterion**：写代码前先写下"什么实验结果会杀死它 + 谁跑、何时跑"。没有 kill criterion 的实验性模块不进 `awareliquid_physics/` 主包。
4. **测量优先于声明**：任何对外数字必须能溯源到 `benchmarks/*.py` 产出的结果 JSON（含 `meta` 溯源块：git_sha / device / ts / seed）+ PRD 表。结果 JSON 的 schema 由 `awareliquid_physics/observability.py::run_metadata` 保证，审计用 `benchmarks/audit_results.py --check`。
5. **平台期 ≠ 终局**：响应顺序固定为 训练方式 → 任务 → 架构（P7 + P2 的历史教训）。
6. **负结果与正结果同等入账**：ADR-4/ADR-7 类负结果必须留在 ADR 表里，不得因后续反转而删除（反转走修订，不涂改历史）。
